# 别卷 0.2 → 1.0 产品路线与 TODO

> 文档用途：作为后续版本规划、开发顺序和发布验收的共同基准。
>
> 当前发布版本：`v0.1.6`（2026-10-06）；上一发布基线：`v0.1.5`（2026-10-05）。
>
> 进入 v0.2 前请先查看 [v0.1 收尾与交接清单](V0.1_CLOSEOUT.md) 和 [补丁说明](RELEASE_NOTES_v0.1.6.md)。局部收尾修复不等于 v0.2 验收通过。
>
> 版本策略：`0.x.0` 代表一个功能里程碑；`0.x.y` 只用于 Bug 修复、回归修复、兼容性修复和安全修复，不在补丁版本中引入新的主要用户功能。

---

## 1. 总目标

将“别卷”从一个功能已经较丰富的刷题工具，逐步提升为：

> **本地优先、数据可靠、普通用户可以独立上手并长期使用的题库与错题复习产品。**

最终 `1.0.0` 不要求必须具备账号、云同步、在线题库市场或社区功能。只要本地版能够可靠完成导入、整理、练习、错题复习、备份恢复和升级迁移，就可以成为完整的正式版本。

核心原则：

- 普通刷题不依赖 AI 和网络。
- 用户数据优先于安装目录和程序本身。
- 外部题库只在边界处兼容，内部统一使用规范结构。
- AI 结果必须可审查、可导出、可恢复，不能把“格式合法”当成“内容正确”。
- 每个里程碑必须有可执行的验收条件，而不是只完成页面或接口。

---

## 2. 当前基线：v0.1.6（沿用 v0.1.5 功能基线）

### 已具备

- Windows Tauri 2 桌面版和 NSIS 安装包。
- Windows 桌面端 API Key 保存到本地配置文件，重启后可恢复。
- 内置题库与用户题库分离，安装包内置资源只读。
- 用户题库、AI 转换题库和图片写入用户数据目录，避免写入 `Program Files`。
- 用户题库可刷新、读取和删除，删除时清理关联练习数据。
- 多种刷题模式、错题本、导入导出基础能力。
- DOCX、PPTX、PDF、XLSX/XLSM、TXT、Markdown、JSON、CSV 等文档转题库流程。
- AI 转换流水线具备结构分析、分段转换、答案匹配、Schema 校验和修复。
- 基础 TypeScript、Rust 和配置检查，以及 API Key、题库管理测试。

### 当前不应默认视为已完成

以下能力虽然可能已经存在部分实现，但必须在对应里程碑中重新核验覆盖范围：

- 题库、错题本、练习进度的完整备份与恢复。
- 异常退出、写入失败和升级后的数据保护。
- 题库导入预览、问题报告和批量校验。
- 题目稳定 ID 与题库变更后的历史记录关联。
- 跨 Windows、Android、Web 的数据迁移边界。
- 大题库、长文档和低配置设备的性能。
- 安装版真实环境下的更新、卸载、重装和权限行为。

# 3. v0.2.0：稳定刷题版

## 目标

让用户可以放心地导入题库、做题、复习错题、关闭并重启程序，而且不会因为普通错误丢失学习数据。

## TODO

- [ ] 盘点当前所有持久化数据：题库、图片、错题本、错题记录、练习进度、设置、AI 配置。
- [ ] 为本地数据增加统一的 `schemaVersion` 和应用数据版本信息。
- [ ] 设计并实现数据迁移入口，至少覆盖 `v0.1.5 / v0.1.6 → v0.2`。
- [ ] 保存采用临时文件 + 原子替换，避免写入中断产生半个 JSON。
- [ ] 写入失败时保留旧数据，并明确提示失败原因。
- [ ] 增加自动备份或最近一次可恢复快照。
- [ ] 实现全量备份：题库、图片、错题本、错题记录和练习进度。
- [ ] 实现全量恢复：恢复前校验，失败时不破坏当前数据。
- [ ] 明确备份是否包含 AI 配置；默认不导出 API Key，若包含必须二次确认。
- [ ] 在设置页展示数据目录、备份入口、恢复入口和当前数据版本。
- [ ] 明确卸载、重装、升级对用户数据的影响，并在界面和文档中说明。

### 3.2 题库导入与校验（P0）

- [ ] 导入前预览文件名、题目数量、题型分布和图片数量。
- [ ] 导入前执行 JSON、Schema、题型、答案和重复 ID 校验。
- [ ] 输出可读的问题报告：题号、字段、原因和修复建议。
- [ ] 空题库、损坏 JSON、未知题型和缺少关键字段不能静默导入。
- [ ] 导入失败时保留原文件，不产生半成品题库。
- [ ] 对 UTF-8、BOM、中文路径、中文文件名和超长文件名做回归测试。
- [ ] 统一内置、手动放入、应用导入和 AI 生成题库的来源标识。

### 3.3 刷题闭环（P0）

- [ ] 核验单选、多选、判断、填空、简答、程序分析、编程和复合题的判题行为。
- [ ] 核验练习、考试、背题、专项练习和错题模式的进度恢复。
- [ ] 核验答题结果、错题归档、错题移除和重新练习之间的数据一致性。
- [ ] 重启程序后恢复必要的练习状态，不恢复已经结束的临时会话。
- [ ] 删除题库时清理关联记录，但不能误删其他题库或共享图片。
- [ ] 对重复点击、快速切页、浏览器刷新、窗口关闭和异常退出做测试。

### 3.4 Windows 发布质量（P0）

- [ ] 在普通用户权限下安装、启动、导入、保存和删除题库。
- [ ] 验证安装目录不可写时，用户功能仍全部写入用户数据目录。
- [ ] 验证覆盖安装不会丢失题库、错题本、进度和配置。
- [ ] 验证卸载后用户数据保留策略符合文档说明。
- [ ] 验证自动更新下载失败、取消授权、安装失败时不会破坏旧版本。
- [ ] 建立一份固定的 Windows 安装版验收清单。

## v0.2.0 验收门槛

- [ ] 新用户可在不修改项目目录的情况下完成：安装 → 导入 → 做题 → 错题复习 → 备份 → 恢复。
- [ ] 模拟写入失败、进程中断和恢复失败，已有数据仍可使用。
- [ ] 至少使用一套包含图片、Markdown、复合题和多种题型的真实大题库完成回归。

- [ ] 没有已知的 P0 数据丢失问题或核心流程阻断问题。

# 8. v1.0.0：正式稳定版

## 产品承诺

> 普通用户无需阅读开发文档，也无需开发者陪同，就能安装应用、导入自己的资料、完成练习和错题复习；遇到失败时能理解原因，已有数据有备份和恢复路径，升级不会破坏学习成果。

## 1.0 必须满足

### 核心使用

- [ ] 导入题库、练习、考试、背题、专项练习和错题复习形成完整闭环。
- [ ] 主要题型在正式支持平台上行为稳定且有格式文档。
- [ ] 练习进度、错题和统计在重启、升级和数据迁移后保持一致。
- [ ] 题库、题目和学习记录之间的身份关系稳定可解释。

### 数据可靠性

- [ ] 一键备份和恢复已验证，覆盖正式支持的数据类型。
- [ ] 备份默认不包含 API Key，恢复前有清晰提示。
- [ ] 写入失败、异常退出、更新失败和磁盘空间不足不会静默破坏旧数据。
- [ ] 数据迁移有版本记录、失败保护和回滚/备份路径。
- [ ] 用户能找到数据目录、备份文件和故障排查入口。

### 可用性

- [ ] 首次启动、空题库、无权限、无网络和 AI 未配置时都有可操作提示。
- [ ] 删除、覆盖、恢复和清空等危险操作有确认和明确后果。
- [ ] 关键操作可使用键盘或辅助操作完成。
- [ ] 普通用户测试可以独立完成主要任务。

### 发布质量

- [ ] 正式支持平台有明确兼容范围和已知限制。
- [ ] 安装包、升级包和发布说明可重复生成。
- [ ] 每个发布资产有版本、大小和 SHA-256 校验信息。
- [ ] P0/P1 缺陷为零；P2 缺陷有明确接受理由和后续计划。
- [ ] 发布后有问题反馈、版本回滚和紧急修复流程。

## 1.0 不作为前置条件

以下功能可以放到 `1.x`，不应阻塞本地优先版 1.0：

- [ ] 用户账号和云同步。
- [ ] 在线题库市场、社区、排行榜和协作编辑。
- [ ] 所有操作系统和所有文档格式的支持。
- [ ] AI 自动判定所有主观题。
- [ ] 复杂的间隔重复算法或个性化推荐系统。

## v1.0.0 发布门槛

- [ ] `v0.6.0 RC` 的所有阻断问题已关闭。
- [ ] 至少完成一次从旧版本升级到 1.0 的真实数据迁移。
- [ ] 至少完成一次备份损坏、恢复失败和更新中断的故障演练。
- [ ] 至少一名非开发者用户独立完成核心任务。
- [ ] 发布文档、用户文档、题库格式文档和已知限制齐全。
- [ ] 功能冻结后只接受 P0/P1 修复，发布候选版本没有新增主要功能。

# 9. 版本和 Bug 修复规则

## 版本含义

| 版本形式 | 用途 | 允许内容 |
| --- | --- | --- |
| `0.2.0`、`0.3.0` | 功能里程碑 | 新增一组完整能力，并完成对应验收 |
| `0.2.1`、`0.3.1` | 补丁版本 | Bug 修复、回归修复、兼容性修复、安全修复 |
| `0.2.2`、`0.3.2` | 补丁版本 | 同上，不新增主要用户功能 |
| `1.0.0` | 正式稳定版 | 完成正式版发布门槛 |
| `1.0.x` | 正式版维护 | 修复问题，不改变数据格式和核心行为，除非有迁移方案 |

## 每个小版本发布前

- [ ] 明确问题复现步骤和影响范围。
- [ ] 为修复补充自动化回归测试，或记录无法自动化的人工验收步骤。
- [ ] 验证不改变备份格式、题库兼容性和数据迁移行为。
- [ ] 更新发行说明和已知问题。
- [ ] Windows 发布包完成安装/升级冒烟测试。
- [ ] 若影响 Android 或 Web，执行对应端回归。

## 不允许进入补丁版本的内容

- 新增完整业务模块。
- 改变题库字段但没有迁移方案。
- 改变备份格式但没有向后兼容说明。
- 改变数据目录而没有迁移和回滚保护。
- 以“顺便重构”为名引入未验证的核心行为变化。

# 10. 推荐执行顺序

1. 完成 `v0.2.0` 数据安全和核心刷题闭环，不急于扩展 AI 功能。
2. 完成 `v0.3.0` 题库维护和稳定 ID，解决长期使用的内容管理问题。
3. 完成 `v0.4.0` 统计和复习体验，让学习结果可解释。
4. 完成 `v0.5.0` AI 质量、跨端数据和性能基线。
5. 完成 `v0.6.0 RC` 的功能冻结、真实用户验收和发布工程。
6. 达到发布门槛后发布 `v1.0.0`；其间只发布 `0.x.y` Bug 修复版本。

> 判断是否可以进入下一个大版本：不要看“代码写完了多少”，要看该阶段的验收门槛是否全部通过。
